# IFC wall authoring intent: issue #321

Source base: `30527e323e9c2e59abff927e4b76fe3ce0f83e15` (0.11.0), Windows 11. Before the fix, IFC save/open changes noncentral wall location lines to `centre` and loses explicit floor top/base attachment identities. `red.log` records two failing public Session regressions.

`wall-intent.txt` is a synthetic CLI model with compound straight/curved walls, door/window openings, floor and roof attachments, and an arbitrary georeference with scale 0.9996. Run `python verify_cli.py <bimcraft-cli-executable>` with IfcOpenShell **0.8.5** installed. It creates IFC/native files, reopens them through the real CLI, compares authored wall locations/axes/arcs and attachment GUIDs, validates EXPRESS rules and builds all represented shapes. `verify_variants.py <bimcraft-cli-executable>` adds translated/rotated placement, metre-unit and triangle-mesh body variants plus the repository's sample house.

The result preserves the five CLI fixture walls' authored choices and references. Original, IFC-reopened and native-reopened output each build **12 shapes**, with zero schema/EXPRESS statements and unique GlobalIds in each file. Bounds and volumes agree. The first wall has hand-calculated net volume **2.5608 m3** after subtracting its door and window, independently checked by IfcOpenShell. All three transformed/unit/body variants also preserve the wall metadata, shapes and grid-to-ground scale. The sample opens with no skipped elements and validates independently. Root and implementer visually inspected both reopened 3D PNGs.

Seven focused regressions pass for all six wall location choices, straight and signed curved axes, endpoint retention, explicit attached/unattached intent, generic inference, malformed metadata and invalid reference targets. The existing IFC-filter group passes **92** tests and the import-filter group **31**; those groups overlap and are not added together. Final logs, core all-target Clippy, translations and the source-reference-only catalog audit are included.

Ancillary `IfcOpeningElement` GUIDs are derived from the imported project's UID by unchanged existing helpers. They can change through IFC reopen even while the authored filling door/window GUID stays stable. The initial verifier's broader GUID assumption and its failure are retained in `cli-verification-initial-auxiliary-guid-assumption.log`. Final comparisons identify those derived opening shapes by their filling element's stable GUID and compare geometry/host relationships. Authored element GUIDs and attachment identities remain directly checked. `unchanged-guid-helper-and-translations.log` records the unchanged helper bodies and catalog audit. Other native wall constraints such as top-level constraints remain outside this fix.

The fix adds standard custom `BIMCraft_Wall` properties without a native schema change. Its IFC GUID categories 61/62 are distinct from grid PR #319's 59/60. Local Cargo checks use uncommitted opt0/debug0 overrides, and the CLI build omits optional DWG/Revit readers. Full workspace/platform/IFC CI results are tracked with the fix PR; no full-workspace local pass is claimed and no tests were disabled or weakened.
