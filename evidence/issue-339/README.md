# Explicit upper-level opening elevation

Synthetic reproduction for IPedrax/BIMCraft issue #339, using only original test geometry.

Base: `30527e323e9c2e59abff927e4b76fe3ce0f83e15` (0.11.0). Platform: Windows 11 10.0.26300. IfcOpenShell: 0.8.5.

`repro.txt` creates one full-height wall and asks for a window 900 mm above an upper level at 3400 mm. The expected absolute sill is 4300 mm. `journey.py` drives the actual standalone CLI, renders the upper plan/elevation/3D, saves native and IFC files, then reopens the native file and renders/exports again. Run from this directory:

```text
python journey.py /path/to/bimcraft-cli red
python inspect_ifc.py red
python journey.py /path/to/fixed/bimcraft-cli green
python inspect_ifc.py green
```

The inspector requires IfcOpenShell 0.8.5; it validates both exports with EXPRESS rules and builds every represented product's world geometry. RED outputs preserve the bug (window/void 0.9–2.4 m). GREEN outputs must show 4.3–5.8 m before and after reopen. PNGs show the same synthetic model, including its upper plan and elevation. Native `.bimcraft` files are original generated bytes, without path rewriting.

The fix keeps `Opening.sill` relative to the host own base. An explicitly requested *different* level is converted to that representation. Omitted/same-host-level placement keeps existing raised-base behavior. Existing width, sill, overlap and host-fit validation/rollback remain authoritative. Level movement after creation does not rehost openings; this is a placement conversion without a native format change.

Local builds use `CARGO_BUILD_JOBS=2`, `RAYON_NUM_THREADS=2`, test threads=4 and uncommitted `profile.dev.package.bimcraft-core.opt-level=0` / `profile.dev.debug=0` overrides. The actual CLI build uses `--no-default-features` to omit optional external DWG/RVT readers. Full workspace/default-feature/platform/IFC CI remains required before merge; local targeted results do not claim those checks passed.
